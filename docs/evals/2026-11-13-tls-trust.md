client and a ReplicatedMergeTree auxiliary Keeper connection for the Keeper

## Boundaries

[Bundle provenance and pinned source analysis](../../ansible/files/README.md)
explain why ClickHouse 26.8's native S3 path uses a shared outbound context.
Explicit ATS roots remain trusted for its outbound inter-node/Keeper clients;
this is not per-endpoint isolation. Keeper, inbound and standalone clients
remain private-CA-only. No live AWS endpoint/account was contacted or credentials
requested. AWS IAM/KMS, real S3 TLS chains, IMDS, RHEL/SELinux and Object Lock
runtime enforcement remain unverified. Object Lock advice and migration limits
